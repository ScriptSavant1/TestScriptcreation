=== 3-TIER CLASSIFICATION SYSTEM ===

TIER 1: DYNAMIC → load.global.varName
  Variables whose values are set at runtime by scripts or extracted from responses.
  Detection rules (in priority order):
    a) Variable is SET in a test/post-response script:
       pm.environment.set("var"), pm.globals.set("var"),
       pm.collectionVariables.set("var"), context.set("var"),
       bru.setVar("var"), bru.setEnvVar("var")
    b) Variable is a correlation target (extracted from a previous response)
    c) Variable has _ prefix AND empty/null value (convention for dynamic vars)
  Resolution:
    - Initialize in load.initialize(): load.global.varName = null;
    - Set after extraction: load.global.varName = webResponse_XX.extractors.varName;
    - Consume via: load.global.varName

TIER 2: PARAMETERIZED → load.params.varName
  Variables from collection/environment with known values, stored in CSV.
  Sub-categories:
    a) CONFIG (nextValue: once) — read once per test run, same for all iterations
       Examples: baseUrl, apiKey, clientId, redirectUrl, apiVersion, endpoints
    b) TEST DATA (nextValue: iteration) — changes per iteration per vuser
       Examples: username, password, email, account, userID
       Special: password uses "nextRow: same as username" to keep pairs linked
  Resolution:
    - Define in parameters.yml with CSV column mapping
    - Store actual values in collection_data.csv
    - Consume via: load.params.varName

TIER 3: GENERATED / SPECIAL
  Postman built-in dynamic variables:
    {{$timestamp}}    → Date.now()
    {{$guid}}         → load.utils.uuid()
    {{$randomInt}}    → Math.floor(Math.random() * 1000)
    {{$isoTimestamp}} → new Date().toISOString()
  Variables starting with $ are NEVER parameterized — replace with JS code.

UNRESOLVED: Variable cannot be classified → // TODO: Replace {{varName}}

=== DETECTION LOGIC (apply in this order) ===

1. Scan ALL scripts for context.set("var") / pm.*.set("var") → DYNAMIC
2. Check correlation targets (extracted from responses) → DYNAMIC
3. _ prefix + empty/null value → DYNAMIC
4. $ prefix (Postman built-in like $randomInt) → GENERATED (skip param)
5. Name matches credential pattern (username, password, email, account,
   user, pwd, login, credential) → PARAMETERIZED (nextValue: iteration)
6. Everything else with a value → PARAMETERIZED (nextValue: once)

================================================================================
  CRITICAL SECOND STEP: 2-PASS CORRELATION ALGORITHM
================================================================================

You MUST run this algorithm before generating the script.

----- PASS 1: SCAN WHAT EACH REQUEST PRODUCES -----

For EVERY request in the collection, in order, check:

  SOURCE A: TEST SCRIPTS (strongest evidence)
  Look in event[].script.exec where listen === "test":

    pm.environment.set("varName", VALUE_EXPRESSION)
    pm.globals.set("varName", VALUE_EXPRESSION)
    pm.collectionVariables.set("varName", VALUE_EXPRESSION)
    bru.setVar("varName", VALUE_EXPRESSION)
    bru.setEnvVar("varName", VALUE_EXPRESSION)

  For each match:
    - varName = the correlation name
    - VALUE_EXPRESSION tells you the JSON path:
        pm.response.json().access_token      --> JSON path: $.access_token
        pm.response.json().data.user.id       --> JSON path: $.data.user.id
        pm.response.json().data[0].id         --> JSON path: $.data[0].id
        jsonData.token                        --> JSON path: $.token
        (where jsonData = pm.response.json())
    - Choose extractor type:
        JSON response  --> JsonPathExtractor
        XML/SOAP body  --> BoundaryExtractor (use XML tags as boundaries)
        Header value   --> BoundaryExtractor with scope: "headers"

  SOURCE B: RESPONSE VARIABLE ASSIGNMENTS (Bruno-specific)
  Look in request.vars.res[]:
    { "name": "userId", "value": "res.body.id", "enabled": true }
  This means: userId = response.body.id --> JSON path: $.id

  SOURCE C: URL PATTERN INFERENCE (when no scripts exist)
  If a request has NO test scripts but its endpoint suggests it produces
  values, use these heuristics:

    Endpoint contains /login, /auth, /signin, /token:
      --> Likely produces: access_token, token, sessionId, userId
    Endpoint contains /oauth/token:
      --> Likely produces: access_token, refresh_token, token_type
    Method is POST and endpoint suggests creation (/users, /orders, /items):
      --> Likely produces: id, createdId

    BUT ONLY infer these if a later request actually CONSUMES the variable.
    Mark all inferred extractions with: // VERIFY: Confirm JSON path

----- PASS 2: SCAN WHAT EACH REQUEST CONSUMES -----

For EVERY request, check ALL these locations:

  LOCATION 1: URL - "{{baseUrl}}/users/{{userId}}/profile"
  LOCATION 2: HEADERS - "Authorization": "Bearer {{token}}"
  LOCATION 3: QUERY PARAMETERS - { "key": "session", "value": "{{sessionId}}" }
  LOCATION 4: REQUEST BODY - "{\"userId\": \"{{userId}}\"}"
  LOCATION 5: PRE-REQUEST SCRIPTS - pm.environment.get("authToken")

Match producers to consumers and print the table:

```javascript
// Section 1: INITIALIZE - runs once per virtual user at start
load.initialize("init", async function () {
    load.log("Initializing Vuser: " + load.config.user.userId, load.LogLevel.info);

    // Initialize dynamic variables (correlation targets, script-set vars)
    load.global.token = null;
    load.global.userId = null;

    // Load external data files (large base64 extracted from request bodies)
    // const fs = require("fs");
    // load.global.docContent = fs.readFileSync(
    //     load.config.script.directory + "/data/Upload_Doc_content.b64", "utf8"
    // ).trim();

    // Authentication setup (OAuth2 token fetch, Basic auth, etc.)
});

// Section 2: ACTION - runs repeatedly (the main load test loop)
load.action("Action", async function () {
    load.log("Starting action - Iteration " + load.config.runtime.iteration, load.LogLevel.info);

    load.WebRequest.defaults.returnBody = false;
    load.WebRequest.defaults.headers = {
        // Browser baseline headers (always include)
        "accept-encoding": "gzip, deflate, br",
        "accept-language": "en-US,en;q=0.9",
        "user-agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
        // Collection-level headers from Bruno request.headers[] or request.scripts[]
        // e.g.:  "X-Api-Key": `${load.params.apiKey}`,
        //        "X-App-Name": "my-app"
    };

    // === TRANSACTION DECLARATIONS (inside action, at the top) ===
    // Variable: TS01, TS02, TS03... (short, zero-padded, sequential)
    // Name: last folder segment (short, readable for LRE reports)
    let TS01 = new load.Transaction("Authentication");
    let TS02 = new load.Transaction("Browse Products");
    let TS03 = new load.Transaction("Create Order");

    // TS01 - Authentication
    TS01.start();

    // Login
    const webResponse_01 = new load.WebRequest({
        id: 1,
        url: `${load.params.baseUrl}/auth/login`,
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: {
            "email": load.params.username,        // PARAMETERIZED (iteration)
            "password": load.params.password       // PARAMETERIZED (iteration)
        },
        returnBody: true,
        extractors: [
            new load.JsonPathExtractor("token", "$.access_token"),
            new load.JsonPathExtractor("userId", "$.user.id")
        ]
    }).sendSync();
    load.log(`Login - Status: ${webResponse_01.status}`, load.LogLevel.info);

    if (webResponse_01.status !== 200) {
        load.log("CRITICAL: Login failed", load.LogLevel.error);
        TS01.stop(load.TransactionStatus.Failed);
        return;
    }
    load.global.token = webResponse_01.extractors.token;
    load.global.userId = webResponse_01.extractors.userId;

    TS01.stop(load.TransactionStatus.Passed);
    load.thinkTime(2);

    // TS02 - Browse Products
    TS02.start();

    // Search Products
    const webResponse_02 = new load.WebRequest({
        id: 2,
        url: `${load.params.baseUrl}/products`,
        method: "GET",
        headers: { "Authorization": `Bearer ${load.global.token}` },
        queryString: { "page": "1", "limit": "20" },
        returnBody: true,
        extractors: [
            new load.JsonPathExtractor("productId", "$.data[0].id")
        ]
    }).sendSync();
    load.log(`Search Products - Status: ${webResponse_02.status}`, load.LogLevel.info);

    load.global.productId = webResponse_02.extractors.productId;
    TS02.stop(load.TransactionStatus.Passed);
    load.thinkTime(1);

    // TS03 - Create Order
    TS03.start();
    // ... more requests as webResponse_03, webResponse_04, etc. ...
    TS03.stop(load.TransactionStatus.Passed);

    load.log("Action complete", load.LogLevel.info);
});

// Section 3: FINALIZE - runs once per virtual user at end
load.finalize("finalize", async function () {
    load.log("Finalizing Vuser: " + load.config.user.userId, load.LogLevel.info);
});
```

=== CRITICAL RULES FOR TRANSACTIONS ===

1. Transaction declarations (let TS01 = new load.Transaction(...)) go
   INSIDE the action function, at the TOP, BEFORE any request code
2. They are NOT declared outside the action or in a separate block
3. Each folder in the collection becomes one transaction
4. Variable naming: TS01, TS02, TS03... (uppercase, zero-padded)
5. Transaction name: LAST segment of folder path only (short for reports)
   "Auth/External Client Apps/OAuth Usage" → "OAuth Usage"
   "Connect/Industries/Fundraising/Gifts" → "Gifts"
6. Duplicate names get _1, _2 suffix: "Query", "Query_1"
7. Every transaction MUST have balanced start() and stop() calls
8. On critical failure: stop(Failed) + return to exit

=== CRITICAL RULES FOR RESPONSE VARIABLES ===

1. Use sequential naming: webResponse_01, webResponse_02, webResponse_03...
2. The number matches the request ID (zero-padded to 2 digits)
3. Each request in the collection gets the next number
4. The request name goes in a comment ABOVE the request (// Login)
5. Do NOT use long descriptive names like Registration_Initialize_response

================================================================================
  LARGE BASE64 VALUE HANDLING
================================================================================

When a request body contains large base64-encoded values (>500 characters):

1. DETECT: Scan JSON body values for base64 pattern (A-Z, a-z, 0-9, +, /, =)
2. EXTRACT: Save the large value to a separate file: data/<RequestName>_<field>.b64
3. DEDUPLICATE: If same content appears in multiple requests, store once
4. LOAD: In initialize section, read the file:
   const fs = require("fs");
   load.global.docContent = fs.readFileSync(
       load.config.script.directory + "/data/Upload_Doc_content.b64", "utf8"
   ).trim();
5. REFERENCE: In the request body, use: load.global.docContent
   (NOT the inline base64 string)

This keeps the script clean and allows testers to swap test documents easily.
