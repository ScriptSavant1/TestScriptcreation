================================================================================
  1. OVERVIEW
================================================================================

  WHAT IS THIS?
  A set of plain text prompt files (.txt) that teach any AI assistant how to
  convert Postman/Bruno API collections into VuGen DevWeb load testing scripts.

  HOW DOES IT WORK?
  You upload the prompt file(s) + your collection JSON to an AI tool.
  The AI reads the instructions and generates complete DevWeb script files.

  WHAT DOES THE AI GENERATE?
  +---------------------+------------------------------------------------------+
  | File                | Purpose                                              |
  +---------------------+------------------------------------------------------+
  | main.js             | The load test script (all requests/logic)            |
  | scenario.yml        | Scenario config (vusers, pacing, duration, rampUp)   |
  | rts.yml             | Runtime settings (timeouts, SSL, etc.)               |
  | tsconfig.json       | TypeScript compiler configuration                    |
  | parameters.yml      | Parameter definitions (when variables exist)         |
  | collection_data.csv | Actual variable values from collection/environment   |
  | data/*.b64          | Extracted large base64 values (if found)             |
  +---------------------+------------------------------------------------------+

  NO CODE REQUIRED. NO PROJECT SETUP. JUST PROMPTS + AI.

  2. WHAT YOU NEED (PREREQUISITES)
================================================================================

  YOU NEED:
  [x] Postman collection exported as JSON (v2.1 format)
      OR Bruno collection exported as JSON
  [x] (Optional) Postman environment JSON file
  [x] The prompt files from the "devweb-prompts" folder
  [x] Access to any AI coding assistant:
      - GitLab Duo
      - GitHub Copilot Chat
      - Claude (claude.ai or Claude Code)
      - ChatGPT (GPT-4 recommended)
      - Any other AI agent

  HOW TO EXPORT FROM POSTMAN:
  1. Open Postman
  2. Right-click your collection
  3. Click "Export"
  4. Choose "Collection v2.1"
  5. Save the .json file

  HOW TO EXPORT ENVIRONMENT FROM POSTMAN:
  1. Go to Environments tab
  2. Click the three dots (...) next to your environment
  3. Click "Export"
  4. Save the .json file

================================================================================
  4. STEP-BY-STEP DETAILED GUIDE
================================================================================

  STEP 1: PREPARE YOUR INPUT FILES
  ---------------------------------
  Gather these files on your desktop or a folder:

    YourCollection.postman_collection.json   (required)
    YourEnvironment.postman_environment.json (optional)
    01-MASTER-PROMPT.txt                     (required - always)
    Additional prompt files                  (optional - see Section 5)


  STEP 2: OPEN YOUR AI TOOL
  --------------------------
  Open one of these:
    - GitLab Duo: Open in your IDE or gitlab.com
    - GitHub Copilot: Open Copilot Chat in VS Code
    - Claude: Go to claude.ai or use Claude Code CLI
    - ChatGPT: Go to chatgpt.com (use GPT-4 for best results)


  STEP 3: UPLOAD FILES + SEND MESSAGE
  -------------------------------------
  IMPORTANT: Upload ALL files in a SINGLE message. Do not send one by one.

  Attach the files and type your message (see Section 6 for templates).

  The AI will:
    a) Read the master prompt (understands DevWeb format)
    b) Parse your collection JSON (extracts all requests)
    c) Analyze authentication, correlations, variables
    d) Generate all output files


  STEP 4: REVIEW THE OUTPUT
  --------------------------
  The AI will output the content of each file with clear headers like:

    === FILE: main.js ===
    (script content)

    === FILE: scenario.yml ===
    (config content)

  Review each file for:
    [x] All requests from collection are included
    [x] Authentication is handled correctly
    [x] Dynamic values (tokens, IDs) are extracted and reused
    [x] {{variables}} are replaced with actual values
    [x] No parameters.yml unless CSV data is truly needed


  STEP 5: COPY FILES TO DEVWEB PROJECT
  --------------------------------------
  Create a new folder for your DevWeb script and copy the generated files:

    MyDevWebScript/
      main.js              <-- The load test script
      scenario.yml         <-- Scenario config (pacing, vusers, duration)
      rts.yml              <-- Runtime settings
      tsconfig.json        <-- TypeScript config
      DevWebSdk.d.ts       <-- Copy from VuGen installation
      parameters.yml       <-- Parameter definitions (if variables exist)
      collection_data.csv  <-- Variable values (if variables exist)
      data/                <-- Large base64 data files (if any)

  Open the folder in VuGen DevWeb to verify and run.


  STEP 6: ITERATE IF NEEDED
  ---------------------------
  If something is wrong, send a follow-up message to the AI:
    "The authentication part is incorrect. Please fix it."
    "Request #5 is missing the authorization header."
    "Please add extractors for the token in the login response."

  You can also upload additional prompt files for specific fixes
  (see Section 5 and Section 7).

================================================================================
  7. HANDLING AI OUTPUT ISSUES (TROUBLESHOOTING)
================================================================================

  ISSUE 1: AI generates parameters.yml with API URLs and configuration
  -----------------------------------------------------------------------
  This is WRONG. parameters.yml should only have CSV test data.

  Send this follow-up:
    "STOP. The parameters.yml is incorrect. Read the attached rules file.
    parameters.yml should ONLY be used for CSV test data (like usernames
    and passwords from a CSV file). API URLs, client IDs, and configuration
    values should be HARDCODED directly in main.js, not parameterized.
    Please remove parameters.yml and hardcode all values in main.js."

  Attach: 07-PARAMETERS-YML-RULES.txt


  ISSUE 2: AI misses dynamic values / correlations
  -----------------------------------------------------------------------
  Tokens, session IDs, or resource IDs are not being extracted.

  Send this follow-up:
    "Some dynamic values are not being correlated. Please check:
    - The login response should extract the auth token using JsonPathExtractor
    - Any created resource ID (from POST requests) should be extracted
    - Use load.global to store and reuse these values
    Please read the attached correlation rules and fix the extractors."

  Attach: 04-CORRELATION-EXTRACTOR.txt


  ISSUE 3: AI generates wrong authentication code
  -----------------------------------------------------------------------
  Auth flow is missing or incorrect.

  Send this follow-up:
    "The authentication is not correct. This collection uses [OAuth2 /
    Bearer / Basic / API Key]. Please read the attached authentication
    rules and regenerate the initialize() section with proper auth setup."

  Attach: 03-AUTHENTICATION-HANDLER.txt


  ISSUE 4: AI does not convert pre-request/test scripts
  -----------------------------------------------------------------------
  Postman scripts are ignored or incorrectly converted.

  Send this follow-up:
    "The collection has pre-request and test scripts that were not converted.
    Please convert them using these rules:
    - pm.environment.set() --> load.global.xxx = value
    - pm.environment.get() --> load.global.xxx
    - pm.response.json() --> JSON.parse(response.body)
    - pm.test() --> if-check after request
    - console.log() --> load.log()
    Read the attached prompt for complete conversion rules."

  Attach: 02-MAIN-JS-GENERATOR.txt


  ISSUE 5: AI skips or ignores Postman scripts (pre-request / test)
  -----------------------------------------------------------------------
  Custom scripts were not converted to DevWeb equivalents.

  Send this follow-up:
    "The collection has pre-request and test scripts that you skipped.
    These MUST be converted to DevWeb format. Please read the attached
    script conversion rules and re-generate the script. Key rules:
    - pm.environment.set() in test scripts --> become EXTRACTORS on the request
    - pm.test() assertions --> become if-checks after the request
    - pm.sendRequest() --> become separate load.WebRequest calls
    - CryptoJS --> use Node.js crypto module instead
    - console.log() --> load.log()
    Do NOT skip any scripts. Convert everything."

  Attach: 09-CUSTOM-SCRIPT-CONVERTER.txt


  ISSUE 6: AI output is truncated / incomplete
  -----------------------------------------------------------------------
  Large collections may exceed AI output limits.

  Send this follow-up:
    "The output was truncated. Please continue from where you stopped.
    Generate the remaining requests starting from [Request Name]."

  Or ask for batch processing:
    "Please split the output into parts:
    Part 1: initialize() section
    Part 2: action() section - first 10 requests
    Part 3: action() section - remaining requests + finalize()"


  ISSUE 6: {{variables}} are not replaced
  -----------------------------------------------------------------------
  Some {{placeholders}} remain in the generated script.

  Send this follow-up:
    "There are still {{variable}} placeholders in the script.
    Please resolve them:
    - If the value is in the collection/environment variables, hardcode it
    - If it comes from a previous response, use load.global.variableName
    - If unknown, add a // TODO comment
    List any variables you could not resolve."

================================================================================
  9. TIPS AND BEST PRACTICES
================================================================================

  TIP 1: ALWAYS UPLOAD 01-MASTER-PROMPT.txt FIRST
    This is the foundation. Without it, the AI does not know DevWeb format.

  TIP 2: UPLOAD ALL FILES IN ONE MESSAGE
    Do not send files one by one. The AI needs to see the prompt AND the
    collection together to generate accurate output.

  TIP 3: USE THE ENVIRONMENT FILE
    If your collection has {{variables}}, the environment file provides
    the actual values. Without it, the AI may leave placeholders.

  TIP 4: REVIEW THE OUTPUT CAREFULLY
    AI-generated scripts are 80-90% accurate. Always review:
    - Are all requests included?
    - Is authentication correct?
    - Are dynamic values properly extracted?
    - Are transaction start/stop balanced?

  TIP 5: ITERATE WITH FOLLOW-UP MESSAGES
    You do not need to start over. If something is wrong, just tell the AI
    what to fix in a follow-up message.

  TIP 6: FOR VERY LARGE COLLECTIONS
    If your collection has 50+ requests, ask the AI to:
    - First: List all requests and folders (analysis)
    - Then: Generate the script in parts

  TIP 7: COPY DevWebSdk.d.ts FROM VUGEN INSTALLATION
    The AI cannot generate the full type definitions file.
    Copy it from: <VuGen Install Dir>/dat/devweb/DevWebSdk.d.ts

  TIP 8: TEST IN VUGEN BEFORE LOAD TESTING
    Always open the generated script in VuGen DevWeb and run a single
    user test (replay) before running a full load test.

  TIP 9: SAVE GOOD OUTPUTS AS REFERENCE
    When the AI generates a good script for a specific collection type
    (e.g., OAuth2 + REST), save it as a reference for similar future
    collections.

  TIP 10: AI TOOL COMPARISON
    - GitLab Duo: Good integration with GitLab CI/CD pipelines
    - GitHub Copilot: Best for in-IDE usage (VS Code)
    - Claude: Best for large collections (200K context window)
    - ChatGPT GPT-4: Good general purpose, may truncate large outputs


================================================================================
  10. FAQ
================================================================================

  Q: Do I need to upload ALL 8 prompt files every time?
  A: No! For most collections, just upload 01-MASTER-PROMPT.txt +
     your collection JSON. Add other prompts only when needed.

  Q: Can I use this with GitLab Duo?
  A: Yes! Upload the .txt prompt file(s) and collection JSON to
     GitLab Duo chat. It works the same way.

  Q: Can I use this with GitHub Copilot?
  A: Yes! In VS Code, open Copilot Chat, attach the files, and
     send your message.

  Q: What if my collection is too large for the AI?
  A: Ask the AI to process in batches. Split by folders or
     request groups. See Template F in Section 6.

  Q: Do I need to know JavaScript to use this?
  A: Basic JavaScript knowledge helps for reviewing the output,
     but you do not need to write any code yourself.

  Q: What if the AI generates wrong code?
  A: Send a follow-up message describing the issue. Upload the
     relevant additional prompt file (see Section 7).

  Q: Can I convert Bruno collections too?
  A: Yes! Upload 08-COLLECTION-PARSING-RULES.txt along with
     01-MASTER-PROMPT.txt and your Bruno collection JSON.

  Q: Do I need the original converter project (Node.js code)?
  A: No! These prompts are completely standalone.
     No code, no npm install, no project setup needed.

  Q: Where do I get the DevWebSdk.d.ts file?
  A: Copy from your VuGen installation directory:
     <VuGen Dir>/dat/devweb/DevWebSdk.d.ts

  Q: Can I customize the prompts?
  A: Yes! The prompt files are plain text. Edit them to add your
     organization-specific patterns, API conventions, or naming rules.
