================================================================================
  PROMPT FILE 10: VuGen Web HTTP/HTML — Action.c & C File Generator Rules
================================================================================

PURPOSE: Rules for generating the C source files for VuGen Web HTTP/HTML protocol.
         Equivalent of 02-MAIN-JS-GENERATOR.txt but for VuGen C scripts.

WHEN TO USE: Upload this file together with 06-MANDATORY-FILES.txt and
             08-COLLECTION-PARSING-RULES.txt when asking Claude to convert a
             collection to --protocol web-http VuGen C scripts.

For the mandatory config files (*.usr, default.cfg, default.usp, ParameterFile.prm,
collection_data.dat, ScriptUploadMetadata.xml) see 06-MANDATORY-FILES.txt.

================================================================================
  OUTPUT FILE STRUCTURE
================================================================================

For --protocol web-http the converter produces 10 files in the output directory:

  Action.c              Main test logic: all HTTP requests + transactions
  vuser_init.c          One-time init per Vuser (auth token fetch, validation)
  vuser_end.c           One-time cleanup per Vuser (logout, resource release)
  globals.h             Standard #include block + global variable declarations
  [ScriptName].usr      VuGen metadata (INI) — open this to load the script in VuGen
  default.cfg           Runtime settings (INI)
  default.usp           Run logic profile (full MercIniTree format — see 06)
  ParameterFile.prm     Parameter definitions (VuGen INI format — see 06)
  collection_data.dat   Parameter values (CSV, header + data rows)
  ScriptUploadMetadata.xml  LRE upload manifest (XML)

If any request body contains large base64 data (>500 chars):
  data/[RequestName]_body.b64   Entire raw base64 body extracted to file
  data/[RequestName]_body.dat   JSON body with embedded base64 field extracted to file

================================================================================
  GLOBALS.H
================================================================================

Always generate with these exact includes. Do NOT add extras unless asked.

```c
#ifndef _GLOBALS_H
#define _GLOBALS_H

/* -------------------------------------------------------------------------------
 *  Script Title  : [collection name]
 *  Protocol      : Web - HTTP/HTML
 *  Generated by  : Bruno to DevWeb Converter
 *
 *  STATIC PARAMETERS  (defined in ParameterFile.prm / collection_data.dat)
 *     {baseUrl}  [once]  default="https://api.example.com"
 *     {username} [per-iteration]  default=""
 *     {password} [per-iteration]  default=""
 *
 *  CORRELATION PARAMETERS  (captured at runtime via web_reg_save_param_*)
 *     {_accessToken}  (extracted at runtime)
 *
 *  HOW TO UPDATE PARAMETER VALUES
 *    1. Open collection_data.dat in a text editor or Excel.
 *    2. Edit values in the data row(s).  Add more rows for additional data sets.
 *    3. Save and re-run.  No recompile needed.
 * ------------------------------------------------------------------------------- */

//--------------------------------------------------------------------
// Standard LoadRunner Includes
#include "lrun.h"
#include "web_api.h"
#include "lrw_custom_body.h"

//--------------------------------------------------------------------
// Global Variables
// Declare C-level variables here to share state between vuser_init(),
// Action(), and vuser_end() that cannot be stored as LR parameters.
//
// Example:
//   char g_accessToken[2048] = "";
//
// Then in vuser_init():
//   strcpy(g_accessToken, lr_eval_string("{_accessToken}"));
//
// And in Action():
//   web_add_header("Authorization", g_accessToken);

#endif // _GLOBALS_H
```

================================================================================
  ACTION.C — OVERALL STRUCTURE
================================================================================

```c
Action()
{
    web_set_sockets_option("SSL_VERSION", "AUTO");    /* ALWAYS first line */

    /* ---- [FolderName] ---- */
    lr_start_transaction("T01_FolderName");

    /* [RequestName] */
    web_add_header("Authorization", "Bearer {_accessToken}");
    web_url("Get_Users",
        "URL={baseUrl}/api/users",
        "Resource=0",
        "RecContentType=application/json",
        "Referer=",
        "Snapshot=t1.inf",
        "Mode=HTML",
        LAST);
    lr_output_message("Get_Users - completed");

    lr_think_time(1);

    web_reg_save_param_json("_userId",
        "QueryString=$.data[0].id",
        "Ord=1",
        LAST);
    web_add_header("Authorization", "Bearer {_accessToken}");
    web_custom_request("Create_User",
        "URL={baseUrl}/api/users",
        "Method=POST",
        "Resource=0",
        "RecContentType=application/json",
        "Referer=",
        "Snapshot=t2.inf",
        "Mode=HTML",
        "EncType=application/json",
        "Body={\"username\":\"{username}\",\"email\":\"{email}\"}",
        LAST);
    lr_output_message("Create_User - completed");

    lr_end_transaction("T01_FolderName", LR_AUTO);
    lr_think_time(1);

    return 0;
}
```

RULES:
1. `web_set_sockets_option("SSL_VERSION", "AUTO")` — ALWAYS the first statement in Action()
2. Transactions wrap folder groups: `lr_start_transaction` / `lr_end_transaction(name, LR_AUTO)`
3. `lr_think_time(N)` between requests inside a group, and between transaction groups
4. `lr_output_message("RequestName - completed")` after EVERY request
5. Request names in web_url/web_custom_request must be valid C identifiers (spaces → underscores)
6. `"Snapshot=tN.inf"` — REQUIRED in EVERY web_url() and web_custom_request() call.
   Counter starts at 1 and increments globally across the entire Action.c script.
   Place it immediately BEFORE "Mode=HTML":
     "Referer=",
     "Snapshot=t1.inf",
     "Mode=HTML",

================================================================================
  WEB_URL() — GET and HEAD requests
================================================================================

Use web_url() for GET and HEAD methods only.

```c
web_url("[safe_request_name]",
    "URL=[url_with_{params}]",
    "Resource=0",
    "RecContentType=application/json",
    "Referer=",
    "Snapshot=tN.inf",
    "Mode=HTML",
    LAST);
```

- No Method= attribute (web_url always implies GET)
- No Body= attribute
- URL may contain {varName} LR parameter references
- `"Snapshot=tN.inf"` — N is a sequential integer starting at 1 across the whole script

================================================================================
  WEB_CUSTOM_REQUEST() — POST, PUT, PATCH, DELETE
================================================================================

Use web_custom_request() for all non-GET/HEAD methods.

```c
web_custom_request("[safe_request_name]",
    "URL=[url_with_{params}]",
    "Method=POST",                        /* POST | PUT | PATCH | DELETE */
    "Resource=0",
    "RecContentType=application/json",
    "Referer=",
    "Snapshot=tN.inf",
    "Mode=HTML",
    "EncType=application/json",           /* Content-Type of the request body */
    "Body={\"key\":\"{value}\"}",         /* JSON: escape " as \" */
    LAST);
```

EncType values:
  "application/json"                  → JSON body
  "application/x-www-form-urlencoded" → URL-encoded form body
  (omit EncType entirely)             → no body (DELETE, etc.)

Body formatting rules:
  - JSON: escape ALL double-quotes with \"
  - LR parameters: use {varName} — NOT {{varName}} (no double braces)
  - URL-encoded: key1={val1}&key2={val2}  (percent-encode keys only, not {params})

LARGE BASE64 BODIES (>500 chars):
  Replace "Body=..." with "BodyFilePath=data/[RequestName]_body.b64"
  VuGen reads the file at runtime and performs {param} substitution within it.
  ```c
  web_custom_request("Upload_Document",
      "URL={baseUrl}/api/documents",
      "Method=POST",
      "Resource=0",
      "RecContentType=application/json",
      "Referer=",
      "Snapshot=tN.inf",
      "Mode=HTML",
      "EncType=application/octet-stream",
      "BodyFilePath=data/Upload_Document_body.b64",
      LAST);
  ```
  If the large base64 is embedded in a JSON field:
  - Write the entire processed JSON to data/[RequestName]_body.dat
  - Use "BodyFilePath=data/[RequestName]_body.dat"
  - {varName} references in the .dat file are expanded at runtime by VuGen

================================================================================
  WEB_ADD_HEADER() — Per-Request Headers
================================================================================

Always emit web_add_header() calls IMMEDIATELY BEFORE the request they belong to.

```c
web_add_header("Authorization", "Bearer {_accessToken}");
web_add_header("Content-Type", "application/json");
web_add_header("X-Custom-Header", "value");
web_url("My_Request", ...);
```

RULES:
- web_add_header() applies only to the NEXT web_url() or web_custom_request() call
- Do NOT set Content-Type via web_add_header if you also set EncType= (duplicate)
- Collection-level headers (same for all requests): emit before every request
- DO NOT use web_add_auto_header() unless specifically required

================================================================================
  CORRELATION — web_reg_save_param_* RULES
================================================================================

CRITICAL: ALL web_reg_save_param_* calls MUST appear BEFORE the request that
produces the value. Placing them AFTER the request means VuGen cannot capture
the response value and {_varName} will be empty.

JSON path extraction:
```c
web_reg_save_param_json("_accessToken",
    "QueryString=$.access_token",
    "Ord=1",
    LAST);
/* web_url or web_custom_request that produces $.access_token comes HERE */
```

Boundary extraction:
```c
web_reg_save_param("_csrfToken",
    "LB=<input name=\"csrf\" value=\"",
    "RB=\">",
    "Ord=1",
    LAST);
/* request that produces the CSRF field comes HERE */
```

Regexp extraction:
```c
web_reg_save_param_regexp("_sessionId",
    "RegExp=session_id=([^;]+)",
    "Ord=1",
    LAST);
/* request that produces the session cookie comes HERE */
```

Using captured values:
```c
/* In subsequent requests: */
web_add_header("Authorization", "Bearer {_accessToken}");
"Body=token={_accessToken}&session={_sessionId}",
```

Naming convention for correlated variables: prefix with `_` (e.g. `_accessToken`,
`_userId`, `_orderId`). Static params from collection_data.dat use no prefix.

================================================================================
  PARAMETER SYNTAX — {varName} vs {{varName}}
================================================================================

In VuGen C code, ALL parameters use single-brace syntax: {varName}
Do NOT use double braces {{varName}} — that is Bruno/Postman template syntax.

| Context                          | Syntax          |
|----------------------------------|-----------------|
| URLs                             | {baseUrl}       |
| Body strings                     | {username}      |
| Header values                    | {_accessToken}  |
| lr_eval_string()                 | "{varName}"     |
| Correlation registration targets | "varName"       |

Examples:
  "URL={baseUrl}/api/users/{_userId}",
  "Body=grant_type=password&username={username}&password={password}",
  web_add_header("Authorization", "Bearer {_accessToken}");
  web_add_header("X-Client-Id", "{clientId}");

================================================================================
  TRANSACTION STRUCTURE
================================================================================

Group requests by top-level collection folder. Each folder = one transaction.

RULES:
1. Name format: T[NN]_[FolderName] where NN is 01, 02, ... and FolderName
   is the folder name with spaces/special chars → underscores (valid C identifier)
2. `lr_start_transaction("T01_FolderName")` — before first request in the group
3. `lr_end_transaction("T01_FolderName", LR_AUTO)` — after last request in the group
4. `lr_think_time(N)` between requests within a group
5. `lr_think_time(N)` between transaction groups (after lr_end_transaction)
6. Do NOT use nested transactions (one level only)
7. ALL transaction names must also appear in [TransactionsOrder] and [Transactions]
   sections of the .usr file — see 06-MANDATORY-FILES.txt

```c
Action()
{
    web_set_sockets_option("SSL_VERSION", "AUTO");

    /* ---- Authentication ---- */
    lr_start_transaction("T01_Authentication");

    web_reg_save_param_json("_accessToken",
        "QueryString=$.access_token",
        "Ord=1",
        LAST);
    web_add_header("Content-Type", "application/x-www-form-urlencoded");
    web_custom_request("Login",
        "URL={baseUrl}/oauth/token",
        "Method=POST",
        "Resource=0",
        "RecContentType=application/json",
        "Referer=",
        "Mode=HTML",
        "EncType=application/x-www-form-urlencoded",
        "Body=grant_type=password&username={username}&password={password}",
        LAST);
    lr_output_message("Login - completed");

    lr_end_transaction("T01_Authentication", LR_AUTO);
    lr_think_time(1);

    /* ---- Users ---- */
    lr_start_transaction("T02_Users");

    web_add_header("Authorization", "Bearer {_accessToken}");
    web_url("Get_Users",
        "URL={baseUrl}/api/users",
        "Resource=0",
        "RecContentType=application/json",
        "Referer=",
        "Mode=HTML",
        LAST);
    lr_output_message("Get_Users - completed");

    lr_think_time(1);

    web_add_header("Authorization", "Bearer {_accessToken}");
    web_reg_save_param_json("_userId",
        "QueryString=$.id",
        "Ord=1",
        LAST);
    web_custom_request("Create_User",
        "URL={baseUrl}/api/users",
        "Method=POST",
        "Resource=0",
        "RecContentType=application/json",
        "Referer=",
        "Mode=HTML",
        "EncType=application/json",
        "Body={\"username\":\"{username}\",\"email\":\"{email}\"}",
        LAST);
    lr_output_message("Create_User - completed");

    lr_end_transaction("T02_Users", LR_AUTO);
    lr_think_time(1);

    return 0;
}
```

================================================================================
  REQUEST NAME SANITIZATION — C IDENTIFIER RULES
================================================================================

Request names in web_url()/web_custom_request() MUST be valid C identifiers.

Rules (apply in order):
1. Replace ALL spaces and non-alphanumeric chars (except _) with underscore
2. Collapse multiple consecutive underscores to single underscore
3. Remove leading/trailing underscores
4. If name starts with a digit, strip the leading digits (e.g. "5_Upload" → "Upload")
5. If name becomes empty after sanitization, use "request"

Examples:
  "Get User Profile"          → Get_User_Profile
  "Login - Step 1"            → Login_Step_1
  "5_Upload_Document"         → Upload_Document
  "POST /api/users/{id}"      → POST_api_users_id
  "Token (OAuth2)"            → Token_OAuth2

================================================================================
  SSL AND SOCKETS SETUP
================================================================================

ALWAYS generate this as the first line of Action():

```c
web_set_sockets_option("SSL_VERSION", "AUTO");
```

This enables automatic SSL/TLS version negotiation. Without it, HTTPS requests
may fail on modern TLS 1.2/1.3 servers.

================================================================================
  VARIABLE CLASSIFICATION FOR WEB HTTP/HTML
================================================================================

In VuGen C, ALL variables use the same {varName} syntax — there is no
load.global vs load.params split. Classification still matters for
ParameterFile.prm (GenerateNewVal) and collection_data.dat.

DYNAMIC variables (correlation targets — registered at runtime via web_reg_save_param_*):
  - Names extracted from response bodies/headers by the script
  - Convention: prefix with _ (e.g. _accessToken, _userId, _orderId)
  - NOT defined in ParameterFile.prm (VuGen manages them internally)
  - Examples: tokens, IDs, CSRF values, session cookies

STATIC PARAMETERS (defined in ParameterFile.prm + collection_data.dat):
  Config (GenerateNewVal="Once") — same value all iterations:
    baseUrl, clientId, clientSecret, redirectUrl, apiKey, version, site, host

  Test Data (GenerateNewVal="EachIteration") — new value per Vuser:
    username, password, email, account, credential, login, userEmail

  Detection logic:
    - Variables set by scripts (context.set, pm.environment.set) → dynamic
    - Names starting with _ and empty value → dynamic
    - Names matching credential pattern (username/password/email) → EachIteration
    - Everything else → Once

================================================================================
  COMPLETE EXAMPLE — FULL TWO-TRANSACTION SCRIPT
================================================================================

Collection structure assumed:
  My API
  ├── Auth
  │   └── Login (POST)
  └── Products
      ├── List Products (GET)
      └── Create Product (POST)

Collection variables: baseUrl=https://api.example.com, username=testuser, password=Test@123

    Script Title       : My API
    Generated by       : Bruno to DevWeb Converter
    Protocol           : Web - HTTP/HTML
   ------------------------------------------------------------------------------- */

Action()
{

    lr_end_transaction("T01_Auth", LR_AUTO);
    lr_think_time(1);

    /* ---- Products ---- */
    lr_start_transaction("T02_Products");

    /* List Products */

================================================================================
  COMMON MISTAKES TO AVOID
================================================================================

1. DO NOT place web_reg_save_param_* AFTER the request — it must come BEFORE
2. DO NOT use double braces {{varName}} in C code — use {varName}
3. DO NOT omit web_set_sockets_option("SSL_VERSION", "AUTO") at top of Action()
4. DO NOT use lr_think_time() as the last statement before return 0 — optional there
5. DO NOT use LR_PASS or LR_FAIL — use LR_AUTO in lr_end_transaction()
6. DO NOT use web_url() for POST/PUT/PATCH/DELETE — use web_custom_request()
7. DO NOT escape {varName} braces in URL= or Body= — they are LR param syntax
8. DO NOT omit "Snapshot=tN.inf" — every web_url() and web_custom_request() call
   MUST include it immediately before "Mode=HTML". The counter starts at 1 and
   increments globally for every request in the entire Action.c script (t1, t2, t3...)
8. DO NOT put inline Body= content exceeding ~4000 chars — use BodyFilePath= instead
9. DO NOT use C++ comments (//) — use C comments (/* ... */)
10. DO NOT forget lr_output_message() after each request — required for logging

================================================================================
  DEVWEB (JS) VS WEB HTTP/HTML (C) — QUICK REFERENCE
================================================================================

| Concept              | DevWeb (JavaScript)                    | Web HTTP/HTML (C)                          |
|----------------------|----------------------------------------|--------------------------------------------|
| Protocol flag        | --protocol devweb (default)            | --protocol web-http                        |
| Main file            | main.js                                | Action.c                                   |
| Language             | JavaScript (ES2019+)                   | C (LoadRunner CCI)                         |
| GET request          | new load.WebRequest({method:"GET",...}) | web_url("name","URL=...",LAST)            |
| POST request         | new load.WebRequest({method:"POST",...}) | web_custom_request("name","Method=POST",...,LAST) |
| Variable syntax      | ${load.params.var} / ${load.global.var} | {varName} (all vars same syntax)          |
| Static param         | load.params.baseUrl                    | {baseUrl}                                  |
| Dynamic var          | load.global.accessToken                | {_accessToken}                             |
| Add header           | headers: { "Auth": ... }               | web_add_header("Auth", "...");             |
| JSON correlation     | new load.JsonPathExtractor(...)        | web_reg_save_param_json("name","QueryString=$.path","Ord=1",LAST) |
| Boundary correlation | new load.BoundaryExtractor(...)        | web_reg_save_param("name","LB=...","RB=...",LAST) |
| Think time           | load.sleep(1)                          | lr_think_time(1)                           |
| Transaction start    | T.start()                              | lr_start_transaction("name")               |
| Transaction end      | T.stop(load.TransactionStatus.Passed)  | lr_end_transaction("name", LR_AUTO)        |
| Log message          | load.log("msg")                        | lr_output_message("msg")                   |
| Large base64 body    | fs.readFileSync("data/x.b64") in init | "BodyFilePath=data/x.b64" in request       |
| Parameter file       | parameters.yml + collection_data.csv  | ParameterFile.prm + collection_data.dat    |
| Config files         | rts.yml, scenario.yml, tsconfig.json  | *.usr, default.cfg, default.usp            |
| Open in tool         | devweb run main.js                     | Open [ScriptName].usr in VuGen             |
