================================================================================
  DEVWEB (JAVASCRIPT) USER GUIDE
  Postman / Bruno → LoadRunner DevWeb Script Converter
================================================================================

  Protocol:   DevWeb (JavaScript) — default output
  Output:     main.js, scenario.yml, rts.yml, tsconfig.json,
              parameters.yml, collection_data.csv, DevWebSdk.d.ts
  CLI flag:   (none — DevWeb is the default)
  Web UI:     Protocol = "DevWeb (JavaScript)" (default selection)

  FOR VUGEN WEB HTTP/HTML (C) OUTPUT: See USAGE-GUIDE-WEB-HTTP.txt
  COMBINED REFERENCE:                 See USAGE-GUIDE.txt

================================================================================
  SECTION 1 — WHAT GETS GENERATED
================================================================================

  Every DevWeb conversion produces:

  ALWAYS GENERATED:
    main.js              — All requests + transactions (async/await, DevWeb SDK)
    scenario.yml         — Vuser count, pacing, ramp-up, duration
    rts.yml              — Runtime settings (HTTP, SSL, proxy, think time) - 10 sections
    tsconfig.json        — TypeScript config for DevWeb SDK type-checking
    DevWebSdk.d.ts       — SDK type definitions (copy from VuGen installation)

  GENERATED WHEN VARIABLES EXIST:
    parameters.yml       — Parameter definitions (type, nextValue, nextRow)
    collection_data.csv  — Parameter values (header row + data row)

  GENERATED WHEN LARGE BASE64 BODIES EXIST (>500 chars):
    data/<name>.b64      — Extracted base64 body (loaded via fs.readFileSync)

  OUTPUT STRUCTURE in main.js:
    load.initialize() {
      load.global.tokenVar = null;          // Tier 1: dynamic (from correlations)
      // Optional: read base64 data files
    }
    load.action() {
      let T01 = new load.Transaction("T01_FolderName");
      T01.start();
      // web_reg_save_param_* equivalents: JsonPathExtractor, BoundaryExtractor, etc.
      let response = await new load.WebRequest({...}).send();
      T01.stop(load.TransactionStatus.Passed);
      load.sleep(1);
    }

================================================================================
  SECTION 2 — PREREQUISITES
================================================================================

  YOU NEED:
  1. An AI tool (GitLab Duo, GitHub Copilot, Claude, ChatGPT, or any AI agent)
  2. Your collection file in ONE of these formats:
       - Postman export: Collection v2.1 (.json)
       - Bruno JSON:     collection.json  (items[] array, no schema URL)
       - Bruno YAML:     opencollection.yml  or  single-request.yml
       - Bruno folder:   Drag the entire /collection folder
       - Single .bru:    One Bruno request file
  3. (Optional) A Postman environment file (.json) for variable values

  SUPPORTED INPUT FORMATS:
  ┌─────────────────────┬───────────────────────────────────┐
  │ Format              │ How to get it                     │
  ├─────────────────────┼───────────────────────────────────┤
  │ Postman v2.1 JSON   │ Export → Collection v2.1          │
  │ Bruno JSON          │ Export → JSON (from Bruno app)    │
  │ Bruno YAML folder   │ Use the collection folder as-is   │
  │ Single YAML .yml    │ Any Bruno .yml request file       │
  │ Single .bru file    │ Any Bruno .bru request file       │
  └─────────────────────┴───────────────────────────────────┘

================================================================================
  SECTION 5 — VARIABLE CLASSIFICATION QUICK REFERENCE
================================================================================

  The 3-tier system is THE most important rule. Apply it BEFORE writing code.

  ┌───────────┬─────────────────────────┬────────────────┬──────────────────┐
  │ Tier      │ Syntax in main.js       │ In params.yml? │ Examples         │
  ├───────────┼─────────────────────────┼────────────────┼──────────────────┤
  │ 1 DYNAMIC │ load.global.varName     │ NO (extractor) │ accessToken,     │
  │           │ (set by extractors or   │                │ userId, orderId,  │
  │           │  initialize() block)    │                │ sessionId, csrf  │
  ├───────────┼─────────────────────────┼────────────────┼──────────────────┤
  │ 2 CONFIG  │ load.params.varName     │ YES            │ baseUrl,         │
  │           │ nextValue: once         │ (nextValue:    │ clientId,        │
  │           │ (same value all iters)  │  once)         │ apiKey, version  │
  ├───────────┼─────────────────────────┼────────────────┼──────────────────┤
  │ 3 DATA    │ load.params.varName     │ YES            │ username,        │
  │           │ nextValue: iteration    │ (nextValue:    │ password, email, │
  │           │ (new value each iter)   │  iteration)    │ accountId        │
  └───────────┴─────────────────────────┴────────────────┴──────────────────┘

  DETECTION PRIORITY (apply in order):
    1. Variable SET by pm.*.set() / context.set() / bru.setVar() → DYNAMIC (Tier 1)
    2. Correlation target (used in extractor) → DYNAMIC (Tier 1)
    3. Name starts with "_" AND empty value → DYNAMIC (Tier 1)
    4. Name starts with "$" (Postman built-in like $timestamp) → SKIP entirely
    5. Name matches credential pattern (username/password/email/account) → DATA (Tier 3)
    6. Everything else → CONFIG (Tier 2)

  CRITICAL PAIRING RULE:
    If both 'username' AND 'password' exist as Tier 3 parameters:
    password must have:  nextRow: "same as username"
    This keeps user/password pairs together across iterations.

  CODE EXAMPLES:
    // Tier 1 — initialized to null, populated by extractor at runtime
    load.global.accessToken = null;
    // ...in action():
    load.global.accessToken = response.extractors.accessToken;

    // Tier 2 — read from CSV once at test start
    const url = `${load.params.baseUrl}/api/v1`;

    // Tier 3 — new row each iteration
    body: JSON.stringify({ username: load.params.username, password: load.params.password })

================================================================================
  SECTION 6 — DEVWEB-SPECIFIC TROUBLESHOOTING
================================================================================

  ISSUE 1: {{variable}} appears as %7B%7B in URLs
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  URL becomes https://api.example.com/%7B%7BbaseUrl%7D%7D
  CAUSE:    AI used new URL() constructor which URL-encodes double braces
  FIX:      "Do NOT use new URL() to parse URLs containing {{variables}}.
             Use string template literals directly:
               const url = `${load.params.baseUrl}/path/${load.params.id}`;
             Or manual string splitting:
               const [base, query] = url.split('?');"

  ISSUE 2: Dynamic token appears in parameters.yml
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  parameters.yml contains an entry for 'accessToken' or 'userId'
  CAUSE:    AI classified a Tier 1 dynamic variable as Tier 2 or 3
  FIX:      "Remove 'accessToken' (and any correlation target) from parameters.yml.
             Dynamic values are NEVER in parameters.yml.
             In main.js: load.global.accessToken = null; in initialize()
             In action(): use a JsonPathExtractor to populate it from the response."

  ISSUE 3: rts.yml has fewer than 10 sections
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  rts.yml only contains httpConnection, ssl, replay (3 sections)
  CAUSE:    AI generated incomplete rts.yml
  FIX:      "Regenerate rts.yml with ALL 10 required sections:
               httpConnection, grpc, proxy, ssl, replay, vts, encryption,
               vuserLogger, flow, thinkTime
             Use the exact template from 06-MANDATORY-FILES.txt."

  ISSUE 4: Correlation extractor placed AFTER the producing request
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  JsonPathExtractor for 'accessToken' is on the response AFTER the
            login call, but load.global.accessToken is never updated before
            being used in the next request
  CAUSE:    Incorrect extractor placement
  FIX:      "The extractor must be ATTACHED to the response of the PRODUCER request.
             Correct pattern:
               const loginResp = await new load.WebRequest({...}).send();
               load.global.accessToken = loginResp.extractors.accessToken;
             The extractor definition goes in the WebRequest that receives the token,
             NOT as a separate statement before or after the request."

  ISSUE 5: password not linked to username
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  Different users' credentials get mixed (user1/password2)
  CAUSE:    password parameter uses nextRow: sequential instead of same as username
  FIX:      "In parameters.yml, the password entry MUST have:
               nextRow: 'same as username'
             This ensures password always advances with its matching username."

  ISSUE 6: Large base64 body hardcoded inline in main.js
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  main.js contains a 10KB+ base64 string inside the body: property
  CAUSE:    AI did not extract large data to a file
  FIX:      "Extract the base64 content to: data/[RequestName]_body.b64
             In initialize():
               load.global.[RequestName]Body = fs.readFileSync(
                 load.config.script.directory + '/data/[RequestName]_body.b64',
                 'utf8').trim();
             In the request:
               body: load.global.[RequestName]Body"

  ISSUE 7: JWT token appearing in parameters.yml
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  parameters.yml contains a jwt_token entry
  CAUSE:    AI classified the JWT token variable as a static parameter
  FIX:      "JWT token variables are ALWAYS Tier 1 dynamic (load.global), never
             parameterized. Any variable set by pm.environment.set() in a
             pre-request script that uses jsrsasign or JWT signing must be
             removed from parameters.yml and initialized as:
               load.global.jwtToken = null;  // in Initialize
             Then populated via jwt-lib.js in the Initialize block (commented out
             — user must configure and uncomment)."

  ISSUE 8: jwt-lib.js not found when running script in VuGen
  ─────────────────────────────────────────────────────────────────────────────
  SYMPTOM:  Error: Cannot find module './jwt-lib'
  CAUSE:    jwt-lib.js was not copied to the script folder
  FIX:      "Copy jwt-lib.js from the project root to the DevWeb script folder.
             It should appear alongside main.js, rts.yml, etc.
             Also ensure it's listed in [ManuallyExtraFiles] in [ScriptName].usr."
