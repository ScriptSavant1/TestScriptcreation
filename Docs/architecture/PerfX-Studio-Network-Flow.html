PerfX Studio — network flow

Which machine talks to which, over what, and in what order — from opening the portal to running a load test. Recordings are processed on the tester's own PC; only collections and test plans travel to the server, and they are held in memory only.

The flow, step by step

  1. 1Open the portal. The browser loads PerfX Studio from the IIS server over HTTPS. IIS hands the request to the Node.js app through iisnode.
  2. 2Download the recorder (once). The tester downloads cdp-recorder.exe from the portal and runs it locally. Nothing is installed.
  3. 3Record the journey. The recorder opens its own Edge or Chrome window. The tester uses the application under test, naming each step from the floating toolbar. The recorder saves recording.har to the local disk.
  4. 4Build the script locally. The HAR is opened in the Recorder or Script Studio, which filter, correlate and produce the script ZIP inside the browser. The recording is never uploaded.
  5. 5Or convert a collection. A Postman or Bruno collection, or a JMeter plan, is uploaded. The server parses, analyses and generates the scripts in memory and streams the ZIP back.
  6. 6Usage event. A small record (which tool, when, browser details) goes to the admin dashboard. It never includes file contents.
  7. 7Hand off to LoadRunner. The tester uploads the ZIP to LoadRunner Enterprise or opens it in VuGen.
  8. 8Run the load test. Load generators run many virtual users against the application under test.
